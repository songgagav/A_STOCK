## 为什么可以判定为伪造值

判定依据是组合证据，而不是仅凭字符串外观：

1. 15 条命中集中在 `tests/test_secret_scan.py`，文件头明确声明这是秘密扫描器的测试夹具，并说明文件级豁免的原因。
2. 命中都位于测试输入、参数化占位符或测试断言中，没有进入运行时配置、数据源连接或执行通道。
3. 测试同时覆盖“应该命中”和“应该忽略”两类控制；如果移除这些合成输入，扫描器就无法证明自己能抓到对应形态，也无法证明不会误报占位符。
4. 当前跟踪文件扫描结果为 0 命中；历史敏感配置路径 `.env`、`config.local.toml` 和 `config_local.toml` 也未出现在 Git 历史中。

## 审计边界与后续规则

- 这 15 条只能作为测试夹具记录，不得在生产环境配置、样例配置或运行日志中复用。
- 若未来发现同一提交之外的新增命中，应先按“疑似真实泄露”处理，再判断是否为测试夹具；不能因为本表存在就自动豁免。
- 修改 `tests/test_secret_scan.py` 后必须运行 `python src/secret_scan.py` 和对应测试，并在审计记录中更新提交、文件和行号。
- 扫描输出必须继续脱敏；报告、CI 日志和告警中不得回显完整疑似值。
