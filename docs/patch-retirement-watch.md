# 估值补丁退役观察期

本文件记录估值补丁从“生产回退源”转为“观察/应急源”时的判据。补丁不是无条件可信的
第二主表：它必须遵守 PIT 可见性、不得覆盖主表已有值，并且每次使用都可审计。

## 当前公开仓库状态

历史台账描述过 `sentinel_daemon.py` 和 `valuation_coverage_sentinel.py` 的自动观察流程，
但当前公开 checkout 不包含这两个运行入口。因此，不能把历史台账中的“每日哨兵”描述当成
当前已启用的生产能力；需要先恢复对应代码、测试和调度配置，再宣布自动观察期成立。

## 退役前检查

在启用自动观察前，必须确认：

1. 主表与补丁重叠区的 PE/PB/EP 口径一致；
2. 补丁只在主表缺失时生效，已有主表值不可被覆盖；
3. 观察任务具备数据版本、运行时间、覆盖率、补丁独有行数和失败原因；
4. 任务失败会告警，不能把空表、异常或缺失依赖当成“0 缺口”；
5. 观察结果能被测试、日志和回放复核。

## 建议判据

观察期至少覆盖 10 个交易日，并逐日记录：

- 主表可用 EP 覆盖率；
- 补丁独有可用 EP 的数量和比例；
- 重叠区值差异；
- 数据版本和代码版本；
- CRITICAL/WARN 次数及处理结果。

若出现任何 CRITICAL、数据版本变化或口径变更，观察期重新计时。只有在观察期内零
CRITICAL、补丁独有增量持续低于约定阈值且回测/选股一致性通过后，才可以关闭自动补丁
回退；即使退役，也应保留只读哨兵和可人工恢复的备份。

## 与发布流程的关系

修改补丁、主表重建或哨兵代码后，必须遵循 [`deployment.md`](deployment.md) 的重启、
源码版本校验和快照新鲜度验收。观察数据属于运行时产物，写入 `data/` 或 `logs/`，不应
提交到 GitHub。
