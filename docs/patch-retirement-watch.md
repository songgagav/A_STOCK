## 3. 哨兵口径修正（观察期首日发现，已修）

观察期第一次运行时，哨兵连续报 4~5 个 WARN，看起来像"上游仍未恢复"。追查后发现是
**哨兵判据本身的口径错误**：

| source | 行数 | `pe_ttm` 非空率 | `pe>0` 率 | `pe<0` 率 |
|---|---|---|---|---|
| `approx_pb_rebuild`（重建） | 60,183 | 70.6% | **70.6%** | 0.0% |
| `snapshot`（上游快照） | 12,593 | 100.0% | **72.0%** | 28.0% |

两个数据源的**可用 `ep` 率其实都是 ~70-72%**，差别只在表示方式：重建把亏损公司的负 PE
置为 `NULL`，而快照保留为负数；而 `ep = 1/pe`（仅取 `pe>0`）在两种情形下都取不到值。

旧判据用"非空率 < 70%"告警，等于把**结构上限**（A 股亏损公司占比约 28%）当成了
**上游缺口**——只要走重建源就会天天误报，观察期证据将无法解读。

修正后主判据改为 **可用 `ep` 率**（`pe_ttm > 0`，主表 ∪ 补丁）：

```
可用 ep 率 < 45%                -> CRITICAL  因子层已实质退化
非空率 < 50% 且可用 ep >= 60%   -> WARN      上游写入缺口(补丁兜底中)
可用 ep 率 < 60%                -> WARN      低于结构区间(实测 65%~72%)
pb < 95%                        -> CRITICAL  估值表大面积缺失
float_shares < 90%              -> WARN      影响 ln_size 市值中性化
```
