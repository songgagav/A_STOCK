# Phase 3.3 路径常量合并：正式关闭

## 结论

不合并三处路径常量定义。

经调用图确认，相关定义分别服务于读取、写入和测试 fixture 等不同边界；
变量文本相似不等于职责重复。强行抽成一个全局变量会引入新的耦合，违反清理阶段
“只清理、不新增行为”的约束。

## 保留规则

- 读取模块保留自己的只读路径边界；
- 写入模块保留自己的输出路径边界；
- 测试 fixture 使用临时目录，不依赖生产路径；
- 不再新增新的硬编码路径；
- 真正需要统一时，优先统一环境变量名称和默认值，而不是强行共享变量。

## 重新开启条件

只有在后续证据显示环境变量命名/默认值不一致造成实际故障时，才另立变更，
并为读取、写入、fixture 分别保留测试边界。
