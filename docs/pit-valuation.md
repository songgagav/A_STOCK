# Point-in-Time 估值数据说明

> 2026-09-12 建立。对应"优先补齐 point-in-time 数据，再做滚动样本外验证"的第一步。

## 实现

- 新增 `db._valuation_asof_h5i(as_of)`：从 `valuation` 表用窗口函数
  `ROW_NUMBER() OVER (PARTITION BY symbol ORDER BY ts DESC)` 取 **`ts <= as_of`** 的每
  symbol 最新一行（窗口 400 天），即严格 as-of 取值，**无前视**。
- `db._universe_asof_h5i(as_of)` 现把上述 PIT 估值 left join 进历史宇宙，新增列：
  `pe_ttm` / `pb` / `ps_ttm` / `total_mv` / `float_mv` / `float_shares` / `is_st`。
- 单位：`market_cap`/`free_cap` 原为"元"，统一转"亿"输出为 `total_mv`/`float_mv`。
- 消费方 `selector.RotationSelector._select_hist`（历史选股/回放路径）由此获得估值特征，
  使 `p08_signal.governance_score` 的 PB/PE 负向过滤与 `db.filter_universe` 的
  **流通市值过滤在历史回测中首次生效**，与实盘读 `valuation_snapshot` 的行为对齐。

### 此前的问题

| 路径 | 估值来源 | 问题 |
|---|---|---|
| 实盘选股 `get_universe()` | `valuation_snapshot` 最新完整快照 | 有估值，但 **`MAX(ts)` 属前视** |
| 历史选股 `get_universe_asof(d)` | 仅 `daily_bars`（价/额） | **无估值字段** → PB/PE 过滤与市值过滤失效 |

结果：回测与实盘存在特征分叉（同一策略在两边看到的信息不同）。现历史路径改为
PIT 正确的 `valuation` 逐日数据，分叉消除。

   下述 12 窗口的"正收益"建立在一个**前视**口径上（窗口落在决策日之前），不构成样本外证据。
   窗口集扩到 **12 个非重叠 120 交易日窗口**（覆盖 2017-12-29 ~ 2026-09-04，两两零重叠），
   结果落 `data/vnpy_backtest_nonoverlap_results.json`；`src/overfitting_test.py` 以
   `OVERFIT_RESULTS_FILE` 指向该文件运行。结论：**12/12 窗口正收益**（收益中位 +27.5%，
   Sharpe 2.25±1.42，最深回撤 -14.78%）。过拟合检测最终 **21 通过 / 0 失败 / 0 警告**。
   同日修正了三处检验/口径缺陷（置换检验、PBO、#8 离群度口径，见下）。

   **#8 口径调整（2026-09-13）**：原为 `max(Sharpe) − median(Sharpe) < 1.0`，该阈值有三个
   问题：①量纲依赖 Sharpe 单位，1.0 无统计含义；②完全由单个最大值决定、对样本量不敏感；
   ③与 [1b]「滚动窗口 Sharpe 稳定性 (CV < 2.0)」重复度量离散度。现改为**稳健 modified
   z-score**：`robust_z = (max − median) / (1.4826 × MAD)`，阈值 **3.5**
   （Iglewicz & Hoaglin 1993 常用离群判据）。该统计量量纲无关、平移不变、对单个离群点
   稳健（MAD=0 时退化为 IQR/1.349 尺度），专门回答原本真正关心的脆弱性问题——
   **整体表现是否被单个离群窗口撑起来**。实测 12 窗口：`robust_z = 1.40`
   （max 4.382 / median 2.242 / gap 2.140 / 1.4826×MAD 1.525 / IQR 2.036），远低于 3.5，
   即最优窗口（2022-12-30, Sharpe 4.38）并非统计意义上的离群点；而同一数据在旧口径下
   （gap=2.14 > 1.0）会被误判 FAIL。离散度本身仍由 [1b] 的 CV 检查覆盖。
   回归测试见 `tests/test_overfitting_dispersion.py`（12 例，含量纲/平移不变性、
   退化序列、200 次正态模拟误报率 ≤ 5%、以及端到端 PASS/FAIL 两向验证）。

   **PBO 修正（2026-09-13）**：原实现用 `max(perm(Sharpe)+noise)` 与 `max(Sharpe)` 比较，
   而 `choice(replace=False)` 只是置换、`max` 恒等于 `max(Sharpe)`，判据退化为"噪声是否
   把其他配置抬过最大值" → `rank <= 1/2`，**`pbo >= 0.5` 恒成立**，`pbo < 50%` 永不可能
   通过（实测 0.7308；7 窗口时 0.5366，均在 0.5 以上），且噪声尺度 `0.5×std(Sharpe)`
   是写死常数。现改为标准 **CSCV-PBO**（`src/pbo_cscv.py` + `scripts/pbo_sweep.py`）：
   以 12 个非重叠窗口为 12 个时间块、以 `top_n × weight_mode` 为 18 组配置，
   扫描出 12×18 收益矩阵后枚举 C(12,6)=924 种 IS/OOS 划分。实测 **PBO=0.0000**、
   λ 均值 2.196（p05=1.322 > 0）、归一化 OOS 排名均值 ω̄=0.885、IS 最优配置 OOS 亏损
   概率 0.000、IS 最优 IS Sharpe 2.659 → OOS 2.548。方法与解读见 `docs/pbo-cscv.md`。

   **置换检验修正（2026-09-13）**：原实现对"窗口汇总值"先 `permutation` 再取 `mean`,
   而均值是置换不变量 —— 置换分布标准差实测仅 ~3e-16（纯浮点误差），p 值完全由
   浮点舍入方向决定（同一数据实测 0.9827，微调数值后为 0.0412），该检查在 n>=12 时
   实质永不可能通过。现改为 **精确符号翻转置换检验**（`sign_flip_test()`）：H0 为
   各窗口收益序列关于 0 对称；把某窗口收益整体取负号时其 Sharpe 精确变为 `-Sharpe`，
   故"独立翻转各窗口符号"恰好给出统计量 `mean(Sharpe)` 在 H0 下的精确随机化分布，
   不依赖正态性/同分布假设。n<=16 穷举全部 2^n 种符号（精确），更多窗口退化为
   固定种子蒙特卡洛并采用 `(1+b)/(1+m)` 估计量避免 p=0。修正后实测：
   单侧 p=**0.000244**（=1/2^12）、双侧 0.000488，两项检查 PASS——即 12 个非重叠窗口
   全部正收益在"无方向性技能"假设下出现的概率仅 1/4096。回归测试见
   `tests/test_overfitting_permutation.py`（9 例，含原假设分布不得退化的守卫）；
   PBO 见 `tests/test_pbo_cscv.py`（10 例，含"PBO 不得退化为常数函数"的守卫）。

5. ⚠️ **前视口径缺陷（2026-09-13 发现，最重要）** —— 第 4 条的正收益结论**全部撤回**：

   | 2018-06-29 | 2017-12-29~2018-06-29 | +36.22 | 2018-06-29~2018-12-21 | **-19.29** |
   | 2021-07-02 | 2021-01-04~2021-07-02 | +70.43 | 2021-07-02~2021-12-27 | +9.33 |

   | 2026-03-05 | 2025-09-01~2026-03-05 | +57.94 | 2026-03-05~2026-08-26 | **-14.64** |
