# 估值主表重建 Runbook

本文只描述公开仓库中的重建流程；原始行情、财务、估值表和备份必须位于本地 `data/`，
不随 Git 提交。

## 触发条件

仅在以下情况触发重建：

- 主源 `financials` 或 `valuation` 的数据版本发生变化；
- PIT 估值口径、补丁覆盖规则或近似 PB 逻辑发生变化；
- 运行哨兵发现可确认的主表缺口，且已完成影响范围评估。

普通代码发布不应顺手重建大表。先记录数据版本、代码提交、配置摘要和预计影响日期。

## 前置检查

1. 停止或隔离会写入同一数据湖的守护和批处理进程。
2. 确认磁盘空间、源表行数、时间范围、唯一键和 `as_of` 边界。
3. 运行 `python src/valuation_backfill.py check`，保存输出。
4. 确认 `data/`、数据库和备份路径已被 `.gitignore` 排除；不要把备份加入暂存区。
5. 记录当前数据版本和旧表统计，作为回滚判据。

## 两阶段执行

### 阶段一：生成与检查近似行

```powershell
python src/valuation_backfill.py approx
```

检查生成文件的日期范围、股票数、正 PB 覆盖率、重复键和 `source` 标记。
近似行只能补主表缺失值，不得覆盖已有 PIT 财务摘要值。

### 阶段二：备份后重建

```powershell
python src/valuation_backfill.py rebuild --approx data/approx_pb_rows.parquet
```

执行必须产生可定位的备份和汇总输出。重建过程中不要同时运行选股、快照发布或补丁写入。

## 执行后验证

至少保存以下结果：

- 重建前后总行数、日期范围、唯一键重复数；
- 主表与近似行重叠区的 `pe_ttm`、`pb` 一致性；
- 亏损公司的 PE/EP 口径没有被误转成正值；
- 随机日期的 PIT 查询不读取未来披露数据；
- 选股快照与实时选股逐位一致；
- 回归测试和非重叠样本外回测没有出现非预期变化。

数据版本变化后，必须使 PIT 缓存、池快照和回测缓存失效或改用新版本命名。

## 回滚

验证失败时立即停止下游发布，保留日志和失败报告，使用重建前备份恢复原表；恢复后重新
执行行数、唯一键、PIT 和选股一致性检查。禁止用删除表或覆盖未知备份的方式“回滚”。

## 相关约束

- `source`、`as_of`、数据版本和备份路径必须写入重建报告；
- 任何无法核实的覆盖率或收益结果标记为未知，不用默认值伪装成功；
- 补丁退役观察期见 [`patch-retirement-watch.md`](patch-retirement-watch.md)。
