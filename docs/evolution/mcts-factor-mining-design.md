# LLM + MCTS 因子挖掘设计

状态：设计稿；不调用外部模型，不生成可生产执行的因子，不绕过现有质量门禁。

## 目标与边界

目标是让语言模型提出可解释的候选表达式，再由受约束的搜索器根据回测反馈探索和精炼；模型只负责候选生成与解释，数据读取、回测、门禁和入库仍由确定性代码控制。

本设计不在当前环境实现。原因是台账尚未完整、降级路径尚未审计、P0-3 风控尚未接线，且真实训练/样本外闭环条件不足。

## 组件

### 1. 表达式语法与白名单

候选必须来自受限 AST，而不是任意 Python：

- 输入：已登记的 PIT 字段和明确的时间序列窗口。
- 操作：加减乘除、rank、zscore、delta、rolling mean/std、截面中性化等白名单操作。
- 约束：窗口为正整数，禁止未来索引、文件/网络访问、任意函数调用和动态代码执行。
- 输出：表达式 AST、规范化字符串、复杂度、使用字段、最大回看窗口。

### 2. MCTS 节点

每个节点代表一个表达式及其评估摘要：

```text
node = {ast, canonical, parent, visits, value, complexity,
        similarity, gate_status, oos_status, provenance}
```

选择阶段使用探索/利用平衡；扩展阶段只从语法白名单添加操作；评估阶段调用隔离回测；回传阶段更新节点统计。搜索预算、随机种子、数据版本和规则版本必须写入实验记录。

### 3. 频繁子树与多样性

对已评估表达式做 canonical AST 归一化，维护频繁子树索引。候选与现有因子过于相似时降低优先级或拒绝扩展；相似度阈值必须在实验配置中版本化，不能由模型自由修改。

### 4. LLM 角色

LLM 输入只包括字段字典、语法、失败约束和脱敏评估摘要；输出必须是结构化候选和经济逻辑说明。解析失败、越权操作、缺字段或无法复现时，候选直接拒绝并记录原因。API key、原始数据和交易记录不得写入 prompt、日志或实验产物。

## 强制质量链

候选因子入库前必须依次通过：

1. 语法/资源安全检查。
2. PIT 可见性与时序对齐检查。
3. 数据质量和缺失率门禁。
4. `factor_gate.py` 的经济逻辑、稳定性和相关性门禁。
5. `overfitting_test.py` 的时间切分、样本外和多重尝试记录。
6. 与现有因子库的相似度/重复性检查。

任何一环失败都只能进入失败经验库，不能自动进入 `factor_library.py` 的生产集合。

## 评估与停止条件

评估至少报告 IC/ICIR、分层收益、换手、成本后收益、行业/规模暴露、缺失率、复杂度和样本外衰减。停止条件包括：预算耗尽、连续若干轮无增益、候选重复率过高、数据版本变化、门禁失败率异常或出现前视迹象。搜索中断必须保留已完成节点和失败原因，恢复时校验数据版本后再继续。

## 未来接线边界

第一阶段只生成研究报告和候选清单；第二阶段才允许研究人员审核后入库；在台账、降级审计、风控接线和样本外证据完成前，不接 `factor_fusion`、`selector`、`target_weighting` 或实盘执行。
