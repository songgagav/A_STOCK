# 市场状态感知与因子路由设计

状态：设计稿；不启用生产路由，不改变当前选股、调仓和风控语义。

## 目标与前置条件

目标是把市场状态作为全截面的条件变量，用于选择或调制因子融合规则，而不是简单新增一个截面因子。第一阶段只允许 shadow 计算和记录，不得影响 `factor_fusion`、`selector`、`target_weighting` 或实盘执行。

正式实现前必须满足：

1. 新的决策、调仓、成交台账连续完整，缺失日显式标记，不用空结果代替。
2. 97 个决策链路与 27 个数据链路降级点完成审计；每个 fallback 都有原因、来源和计数。
3. P0-3 风控动作已由策略负责人决策并完成回测/样本外验收。
4. 现有因子门控、过拟合检验和数据版本校验保持为强制入口。

## 状态定义

第一版只定义四个可解释状态：`bull`、`bear`、`range`、`high_vol`。状态不是由收益标签直接生成，避免把未来收益泄漏到决策日。候选输入只来自决策日前可见数据：

- 市场宽度：上涨比例、涨跌家数比、创新高/新低比例。
- 趋势：指数短中期均线距离、滚动动量。
- 波动：指数实现波动率、波动率分位数、跳跃/极端收益标记。
- 流动性：成交额相对历史分位数、涨跌停/停牌比例。

状态输出必须包含：`state`、`as_of`、`data_version`、输入窗口、每个指标值、置信度、状态判定规则版本。未知或数据不足时只能输出 `unknown`，不能回退成任意正常状态。

## 路由契约

建议先采用可审计的规则路由，不直接引入 MoE：

```text
route(factor_scores, regime_state, factor_history, as_of)
    -> {scores, weights, regime, rule_version, provenance}
```

- `factor_scores` 必须已经通过 PIT 可见性校验。
- `factor_history` 只允许使用 `as_of` 之前的成熟 IC/收益记录。
- 每个状态绑定一组经过冻结版本的因子权重或因子子集。
- 权重必须重新归一化，并对缺失因子显式记录，不可静默补 0 而不留痕。
- `unknown` 状态走当前生产融合规则，作为安全回退；shadow 输出仍须记录。

## 验证与门禁

### Shadow 阶段

同一决策日并行计算当前规则和路由规则，记录：RankIC、分层收益、换手、暴露、缺失率、状态切换次数、与当前组合的持仓差异。shadow 结果不能进入订单或 PaperBook。

### 样本外阶段

- 按时间滚动划分训练/标定/验证区间。
- 状态规则、阈值和权重版本必须在验证区间前冻结。
- 至少覆盖牛、熊、震荡、高波动各一段，并单独报告状态样本数。
- 通过 `factor_gate.py`、`overfitting_test.py` 和 PIT/数据版本门禁后，才允许进入小规模纸面组合。

### 回滚

任何数据版本缺失、状态为 `unknown`、路由结果非有限、权重不满足约束或与当前规则差异超阈值时，回退到当前生产融合规则，并写入审计事件。回滚不能静默发生。

## 不做的事

- 本阶段不接入 MoE、在线学习或实时改权。
- 不用未来收益定义状态，不用全样本统计量回填过去状态。
- 不把研究结果直接接到 `target_weighting` 或实盘调仓。
