feat(roadmap7): 第二轮接线 + 18项盘点 (1940 passed)

用户指定三件接线 + 逐项核对 18 项清单并补齐未落地项。

① 接入现有虚拟盘 —— 卖侧闸门 (src/live_gates.py, 新)
   买入侧此前有单笔合规 + 组合清单, 卖侧**完全没有**闸门。卖侧不能照搬买入侧
   (拒单 = 把风险锁在仓里, 与 kill_switch『只停新开仓, 绝不停离场』同纪律),
   故只查一件可查的事: 账实相符 —— 引擎的"计划卖出量"与账本的"可卖量"由两条
   代码路径算出, 分叉时既不报错也看不出来。处置 = 缩量到可卖成交 + 告警 +
   落订单审计, 绝不取消卖出。容忍度 sell_cash_tolerance=0.10(正常抖动只来自
   当日买入整手取整 <1%)。接线点在 realtime_engine 风控段之后。

② 接入 run_daily —— 三步新步骤
   portfolio_backtest / regime_scenarios / factor_hypotheses, 三者独立容错,
   0 关闭。取数走 src/portfolio_live.py(新): 复用 close_prices_for 的**复权**
   口径(用未复权 close 会在除权日制造假跌, 直接打穿移动止损)与 _limit_prices
   的涨跌停规则; 目标池走 _select_targets_hist(候选目录 C<D 盘前视角),
   **不调用** load_targets(它依赖调用时刻的磁盘状态, 事后跑会停在不同档)。
   多场景步骤避开数据末尾(否则天天假失败)。真机 8 天窗口 3.7s / 13 笔成交。

③ 接入收益评估 (src/factor_hypothesis_eval.py, 新)
   把 factor_hypothesis 的 return_evaluator 接到 factor_mine.evaluator.evaluate。
   fwd5 = adj_close[i+5]/adj_close[i]-1, 跳第 5 根 bar 而非日历 5 天(与
   fml_accumulate.settle_mature 同口径)。收益门槛在 config.FACTOR_HYPOTHESIS_EVAL
   **故意无内置默认值**(缺键抛错) —— 门槛是整条流水线唯一的自由度。
   真机 70 天窗口 363,142 行: return_eval_calls=2, f_mom_rev IC=0.121/ICIR=0.565
   通过、f_vol ICIR=0.275 判否、f_signal 因零截面变异被 lint 拦下。

④ Dead-Man's Switch (src/deadman_switch.py, 新; 清单第6项)
   既有心跳(组件自报活性)与看门狗(数据是否流动)都要求**监测者自己还活着**:
   守护被杀时, 心跳文件停更与"组件没在跑"不可区分。死手开关反过来 —— 周期任务
   必须留下带时间戳的 tick, 3× 标称周期没有 tick 即推定失败, 失联本身即是证据。
   tick 落 data/deadman_ticks.jsonl 并走 #6 哈希链(那一行可改写=告警可抹掉)。
   语义: **账本为空 => UNKNOWN 而非 OK**(监控未生效不等于健康); trading_hours_only
   项在收盘后/周末为 SILENT_EXPECTED 但静默不算正常; CLI 对 OVERDUE 与 UNKNOWN
   都给非零退出码。接线: daemon.py 每分钟 beat、realtime_engine 每轮 beat。

⑤ 连接器能力声明 (src/agent_tools.py, 改; 清单第7项)
   20 个工具全部显式声明能力(read:market/read:kb/read:model/compute/write:artifact/
   write:ledger/veto/order), 不按名字猜。唯一入口 execute() 增加**调用前**能力
   校验(require=/forbid=)。边界不变量: order_tools == [] —— Agent 工具不得直接
   下单, 下单必须走 realtime_engine 的三段式咽喉点。
   这一项同时让第 8 项(角色边界)从口头约定变成可校验事实(is_read_only /
   audit_capabilities)。

接线时抓到并修掉 6 个真 bug(均非测试写错):
   ① factor_mine.evaluator 的 ic_mean/icir/n_days 在**报告根层**而非 report['ic'],
      按嵌套读 => 三门槛全读到 None => **所有假设被静默判否**;
   ② 截面取数逐标的调 close_prices_for 退化成上万次查询并超时, 改一次 SQL 后 9.2s;
   ③ change_pct 口径判别在"恰好集中在 1.0(即 1%)"时判反, 复权序列被放大 100 倍
      (实测 fwd5 算出 +3100%), 改用尾部量级 p99.9(受涨跌停约束的物理量);
   ④ data_lag_days 是**自然日**不是交易日, 按 ==0 判会让每个周一/节后第一天静默停手;
   ⑤ max_single_weight(8%) 是集中度**压回线**不是下单前硬上限, 用它拒单会在目标池
      不足 9 只时拒掉全部买单(被 tests/test_pending_orders.py 9 个用例抓出);
   ⑥ 死手开关 `overdue if led else unknown` 里 led 是 dict, 只要账本有任何条目就为真,
      导致 level 恒为 OVERDUE、UNKNOWN 永不出现。
